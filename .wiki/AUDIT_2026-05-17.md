# hermes-agent — Audit Report 2026-05-17

**Контекст:** инвентаризация форка перед началом V1 Executive OS блюпринта.
**Цель:** понять что покрыто Hermes core, что нужно создать, какие пробелы.
**Метод:** 3 параллельных Explore агента — Structure, Infrastructure, Context.

---

## 1. Structure layer

### 1.1 Skills (`/skills/`)

- **Статус:** ✅ существует, 89 skills в 27 категориях
- **Формат:** `skills/<category>/<name>/SKILL.md` (YAML frontmatter + markdown)
- **Frontmatter поля:** `name`, `description`, `version`, `author`, `license`, `required_credential_files`, `metadata.hermes.tags`
- **Дополнительные папки в каждом skill:** `scripts/`, `references/`
- **Discovery:** автоматический через `scripts/build_skills_index.py`
- **Verdict для V1:** CEO skills положим в `skills/ceo/<name>/SKILL.md` — переиспользуем существующую конвенцию.

### 1.2 Optional skills (`/optional-skills/`)

- 15+ категорий нишевых интеграций (blockchain, communication, health, migration, web-development и др.)
- Не копируются в `~/.hermes/` автоматически, требуют `hermes skills install`
- **Verdict:** для V1 не используем.

### 1.3 Agent core (`/agent/`)

- Python модули: `anthropic_adapter.py`, `bedrock_adapter.py`, `curator.py`, `context_compressor.py`, `context_engine.py`, `display.py`, `error_classifier.py`
- Это **executor** skills, не сами skills.
- **Verdict:** не трогаем без явного запроса. CEO skills работают поверх этого слоя.

### 1.4 Memory-related (СЕЙЧАС)

- `docker/SOUL.md` (13.2 KB, v2026-05-10 v2) — CEO persona + guardrails:
  - 5 поведенческих правил (preflight, question vs action, 95% confidence, ZERO false positives, critique alternatives)
  - Voice memo template `[тип: meeting|decision|insight|recap|task]`
  - Privacy guard (passwords/bank/medical/NDA quotes)
  - Tool priority: memory + session_search PRIMARY, web_search только по запросу
  - Phase 1 boundaries (memory hub only)
  - Interaction model: Telegram @Hermes_Alex21_bot, voice 5+ uses/day
- **Verdict:** база для `memory/soul.md` (canonical). `docker/SOUL.md` остаётся legacy для Docker entrypoint до Stage migration.

### 1.5 Структурные папки `memory/`, `SOP/`, `logs/`, `backups/`

- **Статус:** ❌ отсутствуют на любом уровне
- **Verdict:** создаём в Stage 2 (в корне репо, по блюпринту и user decision).

### 1.6 Scripts (`/scripts/`)

- DevOps/maintenance: `build_skills_index.py`, `build_model_catalog.py`, `contributor_audit.py`, `discord-voice-doctor.py`, `whatsapp-bridge/`, `install.sh`, `release.py`
- **Отсутствует:** backup scripts, telegram bot scripts, cron seed scripts
- **Verdict:** CEO-specific scripts добавляем в `scripts/ceo-os/` (Stage 6+).

### 1.7 Cron (`/cron/`)

- `cron/jobs.py` — определение jobs (1050 LOC)
- `cron/scheduler.py` — main scheduler (tick every 60s)
- Persistence: `~/.hermes/cron/jobs.json`
- Output: `~/.hermes/cron/output/{job_id}/{timestamp}.md`
- **CEO seed jobs (по блюпринту) отсутствуют:** 07:30 brief, 21:30 evening, Sun 17:00 cleanup, Sun 18:00 weekly, 00:30 backup
- **Verdict:** seed в Stage 6 через `hermes cron create` (вне MVP-вертикали).

### 1.8 Plans (`/plans/` + `/.plans/`)

- Минимально: `plans/gemini-oauth-provider.md`, `.plans/openai-api-server.md`, `streaming-support.md`
- **CEO планов нет.** Главный план в `~/.claude/plans/hermes-claude-code-sequential-files-blue-partitioned-gizmo.md`.

## 2. Infrastructure layer

### 2.1 Telegram integration — 70% готово

**Файлы:**
- `gateway/platforms/telegram.py` (3663 LOC, 93 функции)
- `gateway/platforms/telegram_network.py`

**Что работает:**
- `TelegramAdapter(BasePlatformAdapter)`
- Media support, `CommandHandler`, inline buttons
- Topic mode (groups), SQLite migrations
- `send_slash_confirm()` line 1552
- `_handle_command()` line 2956 — точка регистрации команд

**Что отсутствует для V1:**
- ❌ CEO slash commands `/brief`, `/evening`, `/week`, `/capture`, `/projects`, `/area`, `/risks`, `/decision`, `/cleanup`, `/backup`, `/help`
- Команды не зарегистрированы в COMMAND_REGISTRY, нет routing на skill

**Verdict:** Stage 4 — surgical edit `_handle_command()` для регистрации `/brief` → `daily_briefing` skill.

### 2.2 Docker — 100% готово

- `Dockerfile` (84 LOC, production-ready)
- `docker-compose.yml` (60 LOC)
- `docker/entrypoint.sh` (6302 байт)
- Base: `debian:13.4` + Python 3.13, ffmpeg, ripgrep, git, ssh, docker-cli, tini
- Playwright кэш вне volume
- Non-root user `hermes` UID 10000
- Volume: `~/.hermes:/opt/data`

**Verdict:** не трогаем в MVP. Docker миграция SOUL.md → memory/soul.md — следующая итерация.

### 2.3 OpenRouter / Model layer — 100%

- 26+ провайдеров: anthropic, openrouter, nous, openai-codex, copilot, gemini, glm, kimi-coding, minimax и др.
- `cli-config.yaml.example` → `model.default: "anthropic/claude-sonnet-4-6"`
- `OPENROUTER_API_KEY` → `https://openrouter.ai/api/v1`
- `hermes_constants.py` определяет fallback chains
- **Verdict:** не трогаем.

### 2.4 Cron — 80% (infra ready, jobs missing)

**Файлы:**
- `cron/jobs.py` — CRUD для job'ов
- `cron/scheduler.py` — tick loop
- `cronjob_tools.py` — agent-facing API: `create_job_impl()`, `update_job_impl()`
- Delivery: telegram, discord, slack, whatsapp, matrix, email, webhook

**Отсутствует:** 5 CEO seed jobs из блюпринта.
**Verdict:** Stage 6 (out of MVP). `hermes cron create` для каждого.

### 2.5 GitHub Backup — 0%

- `hermes_cli/backup.py` — только local backup в `~/.hermes/hermes-backup-*.zip`
- `agent/curator_backup.py` — snapshot skills перед мутацией (внутренняя логика)
- ❌ Нет push в private GitHub repo
- ❌ Нет `GITHUB_TOKEN` в `.env.example` для backup destination
- ❌ Нет cron job 00:30

**Verdict:** Stage 7 (out of MVP).

### 2.6 SQLite / Memory DB — 100%

- `hermes_state.py` (2630 LOC) — central state layer
- Path: `~/.hermes/state.db` (SQLite 3, WAL mode, foreign keys)
- Таблицы: `sessions`, `telegram_dm_topic_mode`, `telegram_dm_topic_bindings`, `state_meta`
- Миграции через `_reconcile_columns()`
- Auto-maintenance: VACUUM, pruning
- Markdown integration: ❌ нет direct .md storage в state

**Verdict:** оставляем как fast lookup. `memory/*.md` — параллельный long-term layer для CEO.

### 2.7 Security — 80%

**Existing in .gitignore:**
- `.env`, `.env.*`, `*.ppk`, `*.pem`, `privvy*`, `cli-config.yaml`, `skills/.hub/`

**Пробелы:**
- ❌ Нет явного запрета: `tokens/`, `credentials.json`, `secrets.yaml`, `*.key` (только `*.pem`)
- ❌ Нет блока для `/logs/*` (нужно добавить в Stage 2)
- ❌ Нет блока для `/backups/*`

**Verdict:** patch .gitignore в Stage 2.

## 5. Outcome

**Готовности к V1 блюпринту:** ~65% инфраструктурно, ~5% контентно (нет CEO memory files и skills).

**Блокеры для MVP-вертикали `/brief`:**
1. Создать `memory/` структуру с шаблонами (Stage 2)
2. Заполнить `memory/user.md`, `memory/soul.md`, `memory/areas.md`, `memory/projects.md` (Stage 3)
3. Создать `skills/ceo/_lib/memory.py` loader (Stage 3)
4. Создать `skills/ceo/daily_briefing/SKILL.md` (Stage 4)
5. Зарегистрировать `/brief` в `gateway/platforms/telegram.py` (Stage 4)

**Не блокеры (можно отложить):**
- Cron seed jobs (Stage 6) — пользователь может вызвать `/brief` руками для теста
- GitHub backup (Stage 7) — локальный hermes backup работает
- Остальные 5 CEO команд (Stage 5) — `/brief` достаточно для proof-of-concept

**Risk areas:**
- `gateway/platforms/telegram.py` — 3663 LOC, surgical edit требует осторожности
- Personal data в `memory/user.md` — будет извлекать из `docker/SOUL.md` + дополнять placeholder'ами
- `docker/SOUL.md` migration на `memory/soul.md` — оставляем legacy в этой итерации

## 1. Что такое Hermes

Hermes — **Executive Operating System** Александра в Telegram (бот
**@Hermes_Alex21_bot**). Это не чат-ассистент общего назначения, а
**информационное ядро**: долговременная структурированная память CEO
(проекты, риски, решения, цели, ежедневный лог) + быстрый доступ к ней
голосом и текстом.

**Принцип разделения труда:**

- **Hermes = информация + память.** Brief, проекты, риски, поиск по истории
  решений, отчёты. Hermes помнит, структурирует, напоминает.
- **CoS = люди + встречи.** Звонки, координация с командой и партнёрами,
  follow-up, подготовка встреч, всё, что требует живого человека.

CoS работает **рядом** с Hermes, а не вместо него. Hermes даёт тебе контекст;
ты превращаешь контекст в действия с людьми.

**Стадия проекта:** Phase 1 (Memory Hub). Hermes сейчас — справочно-
информационный слой. Он НЕ пишет письма, НЕ ведёт переговоры, НЕ шлёт
сообщения от имени Александра. Это сознательная граница фазы.

## 2. Команды Hermes

Команды доступны в Telegram DM с ботом. Наберёшь `/menu` — бот всегда напомнит
актуальный список.

### Каждый день

| Команда | Что делает |
|---|---|
| `/brief` | Утренний фокус CEO — приоритеты дня (авто в 07:30 EEST) |
| `/evening` | Вечерний recap дня, можно голосом (авто-prompt ~21:30) |
| `/capture <текст>` | Записать мысль / задачу / решение (голосом — автоматически распознаётся) |
| `/diary` | Дневник дня + протоколы встреч (append-only, в логах) |

### Еженедельно

| Команда | Что делает |
|---|---|
| `/week` | Weekly CEO review, можно голосом (авто в воскресенье) |

### Просмотр памяти

| Команда | Что делает |
|---|---|
| `/projects` | Активные проекты (опц. `/projects high` — только высокий приоритет) |
| `/risks` | Топ-риски (опц. `/risks high`) |
| `/find <запрос>` | Поиск по памяти — «что мы решили / когда это было» |
| `/notes` | Структурированные заметки встреч и протоколы (с синком в Obsidian) |

### Коуч и развитие

| Команда | Что делает |
|---|---|
| `/coach` | Персональный коуч CEO (ICF / GROW / Колесо баланса). **Личное — CoS не использует** |

### Внешний контекст

| Команда | Что делает |
|---|---|
| `/web <запрос>` | Веб-поиск с цитированием источника |
| `/report [week\|month\|quarter]` | HTML-отчёт из памяти (можно делиться с командой) |
| `/dashboard` | Кокпит «что на столе сейчас + впереди» — HTML, как /report |

### Утилиты

| Команда | Что делает |
|---|---|
| `/menu` | Главное меню — все команды одним сообщением |
| `/start` | Стартовое приветствие + меню |
| `/remind <когда> <что>` | Напоминание («через 3ч», «завтра в 10:00») |
| `/backup` | Ручной бэкап памяти |
| `/cost` | Сводка по расходам на LLM |
| `/telemetry` | Статистика использования бота |
| `/whoami` | Показать свой Telegram Chat ID (нужно при выдаче доступа) |
| `/cleanup` | Гигиена памяти (предложения). **Александр only — CoS не использует** |

> В списке 21 команда. Личные (CoS не использует): `/coach`, `/cleanup`.
> 22-я — `/handoff` (управление доступом) — командная, использует Александр.

## 3. Разделение труда: Hermes vs CoS

| Зона | Hermes | CoS |
|---|---|---|
| Память и контекст | ✅ источник истины | читает через бота |
| Brief / проекты / риски | ✅ генерирует | использует для подготовки |
| Встречи с людьми | — | ✅ организует, ведёт, фиксирует |
| Звонки и координация | — | ✅ |
| Follow-up с партнёрами | — | ✅ (живой человек, не бот) |
| Подготовка к переговорам | даёт контекст из памяти | ✅ проводит |
| Запись в память | через команды Александра | ❌ нет write-доступа |

**Правило:** если задача про **информацию** — спроси Hermes. Если про
**людей и время** — это твоя зона.

## 4. Границы приватности (обязательно прочитать)

CoS получает **read-доступ** к рабочему контексту, но **НЕ ко всему**.
Privacy guard зашит в сами skills Hermes — некоторые данные не показываются
никому, кроме Александра.

**CoS видит:**
- Рабочий контекст: проекты, риски, рабочие решения, поиск по истории
- Brief дня, отчёты для команды
- Навигацию по командам (`/menu`)

**CoS НЕ видит и не запрашивает:**

| Данные | Почему |
|---|---|
| Здоровье, энергия, стресс (`/coach`, дневник) | Личное Александра |
| Банковские данные, точные суммы договоров | Финансовая тайна — только диапазоны |
| Семейные имена и личные заметки | Privacy guard: семья → роли («Супруга», «Мама», «Папа») |
| Пароли, медицинские данные | Никогда не хранятся в системе |
| NDA-цитаты со встреч | Защищены, переписаны как «своё суждение» |

**Псевдонимы.** Если в рабочем контексте встречаешь «партнёр X», «поставщик Y»,
«клиент Z» — это намеренная анонимизация. Не пытайся раскрыть реальные имена
через бота; если нужно знать — спроси Александра лично.

**Write-доступ остаётся за Александром.** CoS не записывает в память от своего
имени и не отправляет сообщения третьим лицам от имени Александра. Это граница
Phase 1.

## 5. Ежедневный и еженедельный ритм

### Ежедневно

1. **Утро.** Александр получает `/brief` (07:30). Ты синхронизируешься с ним
   по фокусу дня — что из brief требует действий с людьми.
2. **День.** Координация встреч, звонков, follow-up. Контекст по проекту/риску
   берёшь через `/projects`, `/risks`, `/find`.
3. **Вечер.** Александр делает `/evening` (recap). Ты передаёшь ему, что
   закрылось / повисло по людям, чтобы это попало в его вечерний обзор.

### Еженедельно

- **Воскресенье.** Александр делает `/week` (weekly review). К нему ты готовишь
  сводку по людям/встречам недели: что состоялось, что перенеслось, кого
  нужно дожать.
- **Отчёты.** `/report week` даёт HTML-снимок для команды — используешь как
  основу для координации, не как замену живой коммуникации.

## 6. Эскалация

Когда передавать наверх / решать самому:

| Ситуация | Действие |
|---|---|
| Нужны данные, которых нет в Hermes | Спроси Александра лично — не угадывай и не выдумывай |
| Запрос на доступ к health/bank/family данным | Эскалация Александру — приватная зона, не обходить |
| Партнёр просит решение по цене/договору | Эскалация — финансовые решения за CEO |
| Нужно отправить сообщение от имени Александра | Эскалация — Phase 1 запрещает делегацию отправки |
| Hermes выдал «нет данных» / fail-loud | Это норма, не баг — данные просто не записаны. Сообщи Александру, чем дополнить память |
| Срочное по людям/встречам в твоей зоне | Решай сам, потом синхронизируйся в `/evening`-цикле |

**Принцип эскалации:** информация и приватность → к Александру. Люди и
координация в рамках известного контекста → твоя зона.

## 7. Как тебе выдаётся доступ

1. Ты пишешь боту `/whoami` со своего телефона → получаешь свой **Chat ID**.
2. Передаёшь Chat ID Александру **лично** (не в бота).
3. Александр добавляет тебя в allowlist на Railway (`/handoff` procedure).
4. После редеплоя бот начинает отвечать тебе.

Отзыв доступа — мгновенный: Александр убирает твою запись из allowlist.
Проверить текущий состав доступа можно командой `/handoff status` (показывает
записи в redacted-виде, только последние 3 цифры ID).

# /calendar — Google Календарь для CEO

**Цель:** показывать расписание и (по подтверждению) создавать события через уже
подключённый Google-аккаунт (OAuth, токен `/opt/data/google_token.json`).

## Движок

```
HERMES_HOME=/opt/data /opt/hermes/.venv/bin/python \
  /opt/hermes/skills/productivity/google-workspace/scripts/google_api.py calendar <action> ...
```

Sub-actions: `list --start ISO --end ISO --max N [--calendar EMAIL]` · `create` · `delete`.

## Календари владельца — один контур (2026-09-23)

Расписание живёт в трёх календарях; все три доступны подключённому аккаунту
(два расшарены с правом изменений). При любом вопросе «что у меня», «что завтра»,
«свободен ли я» читать **все три** и склеивать в один список по времени:

| Календарь | `--calendar` |
|---|---|
| основной подключённого аккаунта | без флага |
| Alexandr Scerbina (личный) | `scerbinaalexandr@gmail.com` |
| Alexandr Scerbina (второй) | `alexandr.scerbina@gmail.com` |

- Из какого календаря событие — говорить только если владелец спросил или если
  два события наложились: тогда назвать оба и предупредить о накладке.
- Новое событие по умолчанию создавать в `scerbinaalexandr@gmail.com` (основной
  личный); владелец сказал «во второй» — тогда `alexandr.scerbina@gmail.com`.
- Дубли: одна и та же встреча может лежать в двух календарях (так было 19.09) —
  показывать один раз, не «двоить» день.
- Вернулось 404/Not Found — доступ к календарю сняли; сказать об этом прямо и
  не выдумывать события.
- Со временем останется один календарь — список выше тогда сократить.

## Steps

1. **Определить диапазон дат** под запрос (используй текущую дату из системы):
   - «сегодня» → start=сегодня 00:00Z, end=завтра 00:00Z
   - «на неделе / эта неделя» → start=сегодня, end=+7 дней
   - «завтра» → завтрашние сутки. Без уточнения — ближайшие 7 дней.
2. **Выполнить** `calendar list --start ... --end ... --max 15` (см. Движок).
3. **Показать по-русски**, scannable: по дням → «время — событие — место/участники».
   Если пусто — честно «📅 На <период> событий нет» (НЕ выдумывать — soul.md §4a/§4c:
   никаких несуществующих встреч/времён).

## Создание / изменение событий (Phase-1 граница)

- Hermes **НЕ создаёт и не удаляет события сам**. По запросу «поставь встречу» —
  показать черновик (дата/время/название/участники) и выполнить `calendar create`
  **ТОЛЬКО** после явного подтверждения CEO.

## What NOT to do

- ❌ НЕ выдумывать встречи, время, участников (soul.md §4a/§4c) — пусто значит пусто.
- ❌ НЕ создавать/удалять события без явного подтверждения CEO.
- ❌ НЕ путать аккаунты — если запрошен чужой расшаренный календарь, использовать `--calendar`.

# Plaud → протокол

**Поток.** `plaud_pull.py` (no_agent cron, каждые 30 мин) → `plaud recent --days 2`
→ новые записи с транскриптом → `plaud/raw/<id>/` → поручение протоколисту
(`/assign --role scribe`) → протокол в карточке, итог владельцу в Telegram.
Записи короче 60 с пропускаются. Ledger `plaud/seen.json` пишется только после
создания карточки — повтор крона дублей не даёт.

**Ошибки.** Токен протух (exit 2) → одна строка владельцу раз в сутки:
«Plaud отключился — нужно заново войти…». Сеть/таймаут → тихо, следующий тик.
Диагностика — `logs/plaud.log`, в чат не попадает.

**Секрет.** `/opt/data/.plaud/tokens.json` (chmod 600) — владелец получает его
на Mac (`plaud login`) и переносит сам. В git, бэкап и логи не попадает.
Скрипт работает с `HOME=/opt/data`, CLI читает `~/.plaud/tokens.json`.

## Настройка (один раз, владелец на Mac)

```bash
npm install -g @plaud-ai/cli && plaud login          # браузер, вход в Plaud
# затем один раз: bash <скрипт из scratchpad>: переносит токен на волюм и создаёт крон
```

Крон (на проде, от пользователя hermes):
```bash
hermes cron create "*/30 * * * *" --script plaud_pull.py --no-agent \
  --name plaud_pull --deliver telegram
```

## Если владелец спрашивает «что с записями»

`tail -20 $HERMES_HOME/logs/plaud.log` и ответ по-человечески: сколько записей
разобрано за сегодня, есть ли отключение. Технические строки не показывать.

## Что навык НЕ делает
- Не расшифровывает аудио сам (это делает Plaud); не трогает голосовые в Telegram (Groq).
- Не ставит задачи на доски — протоколист перечисляет их, владелец подтверждает.
